# Удаление и принудительное завершение попыток

## Что проверено и изменено

В опубликованном интерфейсе есть кнопка удаления, а в исходнике GitHub разрешено удаление attempts. Текущий workflow Publish FSO Center публикует только папку site на GitHub Pages; он не разворачивает Supabase Edge Function. Наличие исправления в репозитории само по себе не означает, что функция fso-api обновлена. Авторизованная проверка текущей функции Supabase на действующей базе не проводилась.

Новые возможности:

- «Завершить» для попытки «В процессе»: сервер рассчитывает балл по сохранённым ответам, оставляет результат в истории и отмечает, что завершение выполнено администратором. Неотвеченные вопросы считаются неверными. Ответы после завершения не меняются.
- «Завершить и удалить»: сервер завершает активную попытку и удаляет её в одной транзакции. Старый токен больше не даёт доступа; остальные попытки и экзамен не удаляются.
- Для законченных попыток доступно обычное удаление с подтверждением.
- Если Supabase ещё не обновлён, панель показывает подсказку; отказ старого API при удалении объясняет необходимость обновить fso-api.

Использован вариант принудительного завершения администратором. Автоматического завершения при закрытии вкладки нет: закрытие браузера не гарантирует доставку запроса серверу. Существующее завершение по лимиту времени остаётся: истёкшие попытки закрываются сервером при следующем обращении к API, в том числе при обновлении результатов администратором.

## Обновление исключительно через браузер

1. Распакуйте `preview/fso-results-fix.zip`.
2. В репозитории GitHub загрузите содержимое папок по исходным путям. В том числе добавьте файл `.github/workflows/deploy-api.yml` — это отдельный запуск публикации серверной функции. Папка `.github` должна находиться в корне репозитория, а не внутри `preview`.
3. Дождитесь успешного завершения существующего **Publish FSO Center** в Actions. Это обновит интерфейс.
4. В Supabase откройте настройки своего аккаунта → Access Tokens и создайте токен для CLI. Скопируйте его сразу в секрет репозитория GitHub: **Settings → Secrets and variables → Actions → Secrets → New repository secret**, имя `SUPABASE_ACCESS_TOKEN`. Не добавляйте значение в файлы или сообщения.
5. На соседней вкладке **Variables** создайте repository variable `SUPABASE_PROJECT_REF`, значение `rnkmfpjzmvdnpijpeayw` (для другого проекта используйте его ref).
6. В GitHub откройте **Actions → Deploy FSO API → Run workflow**, выберите main и запустите. Дождитесь зелёного результата. При сбое откройте шаг Deploy Supabase Edge Function: проверьте секрет, project ref и доступ владельца токена к проекту.
7. На сайте нажмите Ctrl+F5, при необходимости войдите администратором повторно. В «Результаты и статистика» больше не должно быть сообщения об устаревшей функции. Создайте отдельную тестовую попытку, проверьте «Завершить», затем «Удалить». Для другой активной тестовой попытки проверьте «Завершить и удалить».

Альтернатива шагам 4–6: в существующем Codespace с действующей авторизацией Supabase CLI обновите файлы и выполните:

```bash
git pull origin main
npm test
npx --yes supabase@latest functions deploy fso-api --project-ref rnkmfpjzmvdnpijpeayw --no-verify-jwt --use-api
```

SQL-миграция или переинициализация базы не нужны. `site/config.js`, локальная база и учётные данные в пакет не включены. Новые функции не удаляют существующие записи до подтверждения администратором.
