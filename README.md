# ФСО — пробная справочно-экзаменационная система

Система для игровой организации, созданная на основе интерфейса `fso-center.zip`.
Исходник сохранён в `archive-review/fso-center/`. Рабочий интерфейс находится в `site/`.
Демонстрационные материалы не являются действующим законодательством или уставом.

## Быстрый локальный запуск

Нужен Node.js 22.13 или новее (рекомендуется 24). Зависимостей для установки нет.

```powershell
node server.mjs
```

Откройте http://127.0.0.1:4173. При наличии npm также работает `npm start`.

Первый локальный вход администратора:

- имя: `admin`
- пароль: `FsoDemo2026!`
- кодовое слово пробного экзамена: `АКАДЕМИЯ` (регистр важен)
- пример удостоверения: `123_456`

Эти реквизиты действуют только для локальной пробной версии. Сервер слушает
`127.0.0.1`, поэтому по умолчанию доступен лишь с этого компьютера.
Для своих реквизитов задайте `FSO_ADMIN_LOGIN` и `FSO_ADMIN_PASSWORD` **до первого запуска**.
После создания `.runtime/settings.json` переменные не перезаписывают учётную запись.
Локальный пароль хранится как scrypt-хеш с солью. В интерфейсе смена пароля пока не предусмотрена.

Данные всех посетителей локального сервера сохраняются в SQLite: `.runtime/database.sqlite`.
При перезапуске они остаются. `.runtime/settings.json` хранит хеш пароля и серверный pepper:
Для полной копии остановите сервер и сохраните `database.sqlite` и `settings.json`;
при копировании работающего сервера также нужны SQLite-файлы `-wal` и `-shm`.
В Git эти файлы не попадают. Учётная сессия администратора после перезапуска сервера сбрасывается.
Если остался `database.json` от раннего пробного запуска, он импортируется при первом создании SQLite.

## Что можно проверить

1. Открыть справочник и поиск материалов.
2. Пройти общедоступный тренировочный тест и посмотреть процент результата.
3. Начать экзамен, введя звание, ФИО персонажа, удостоверение и кодовое слово.
4. Выбрать ответы, обновить страницу и убедиться, что попытка восстановилась.
5. Завершить экзамен и открыть результат в кабинете администратора.
6. Отфильтровать результаты по ФИО/удостоверению, экзамену, типу и статусу; выгрузить CSV.
7. Создать материал, вопрос, тест или экзамен; изменить публикацию и кодовое слово.

Курсантам не нужны отдельные аккаунты. Ссылка на последнюю попытку хранится в
`sessionStorage` текущей вкладки. После закрытия вкладки персональное восстановление
не гарантируется; запись на сервере остаётся. Общий код не подтверждает личность сотрудника.

## GitHub Pages + Supabase

GitHub Pages публикует только `site/`. Локальный `server.mjs` там не запускается.
Для общего сайта нужен отдельный проект Supabase. Секретные ключи нельзя помещать в `site/config.js`.

### 1. База и администратор

1. Создайте проект Supabase.
2. Выполните `supabase/migrations/202610050001_trial.sql` в SQL Editor или через миграции CLI.
3. В Authentication создайте администратора с настоящим email и паролем,
   подтвердите его email и скопируйте UUID пользователя.
4. Отключите публичную регистрацию: посетителям не нужны аккаунты.

Для пробной версии используется таблица `fso_state`: один версионируемый JSONB-документ
с материалами, вопросами, проверками, попытками и ответами. PostgreSQL обеспечивает
постоянное хранение, а функция `fso_commit` предотвращает потерю параллельных изменений
через проверку версии и повтор операции. Прямой доступ `anon`/`authenticated` закрыт.
Этот формат удобен для первого запуска; при росте базы его следует разделить на
таблицы сотрудников, вопросов, попыток и ответов с индексами и постраничной загрузкой.

### 2. Начальные данные

Сгенерируйте случайный pepper (например, 32 байта) и задайте его в переменной окружения
`FSO_CODE_PEPPER`; код экзамена — в `FSO_EXAM_CODE`. Значение pepper должно совпадать
с секретом серверной функции и оставаться постоянным. Затем:

```powershell
node scripts/seed-sql.mjs
```

Выполните полученный `supabase/seed.sql` в SQL Editor. Он не заменяет существующие данные.
Файл содержит хеш кода, не сам код и не pepper. Демонстрационный код `АКАДЕМИЯ` не
назначается автоматически в облачной версии: выберите собственный.

### 3. Серверная функция

Установите Supabase CLI на своей машине, войдите и свяжите проект:

```text
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase functions deploy fso-api --no-verify-jwt
```

`--no-verify-jwt` нужен для открытых тестов и справочника. Административные операции
отдельно проверяют JWT через Supabase Auth и разрешённый UUID администратора.

Задайте секреты через Dashboard → Edge Functions → Secrets:

| Секрет | Значение |
|---|---|
| `FSO_ADMIN_UID` | UUID созданного администратора |
| `FSO_ADMIN_LOGIN` | Имя для входа, например `academy_admin` |
| `FSO_ADMIN_EMAIL` | Email его учётной записи Supabase Auth |
| `FSO_CODE_PEPPER` | Случайный секрет, использованный для начальных данных |
| `FSO_SITE_ORIGIN` | Только origin сайта, например `https://yourname.github.io`, без пути репозитория и конечного `/` |

`SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` доступны в размещённой Edge Function
как встроенные секреты. Service-role ключ используется только сервером.
Настройки администратора в данной версии предусматривают одну учётную запись.
Администратор вводит имя и пароль; сервер сопоставляет имя с email Supabase Auth.
Сессия действует до истечения токена; после этого требуется повторный вход.

### 4. Конфигурация интерфейса и публикация

В `site/config.js` установите:

```js
window.FSO_CONFIG = {
  mode: 'supabase',
  supabaseUrl: 'https://YOUR_PROJECT_REF.supabase.co',
  publishableKey: 'YOUR_PUBLIC_PUBLISHABLE_OR_ANON_KEY'
};
```

Это публичный ключ с ограниченными правами, не `service_role`.

Создайте репозиторий GitHub, загрузите проект в ветку `main` и выберите
Settings → Pages → Source: GitHub Actions. Workflow `.github/workflows/pages.yml`
выполнит тесты и опубликует `site/`. Все пути интерфейса относительные, навигация
использует hash, поэтому сайт работает в подкаталоге репозитория без настройки SPA-rewrite.

Перед публикацией убедитесь, что `mode` переключён на `supabase`: конфигурация
`local` намеренно не работает на публичном хосте.

## Проверки

```powershell
node --test tests/*.test.mjs
```

Проверяются закрытый доступ администратора, отсутствие ключей ответов до завершения,
коды/лимиты попыток, формат удостоверения, защита попыток токеном, серверный балл,
истечение времени, неизменность истории, CRUD и сохранение после перезапуска.

Облачные миграции и Edge Function необходимо проверить на вашем Supabase-проекте:
локальные тесты покрывают общий модуль логики и локальный HTTP-сервер, а не облачный транспорт.

## Ограничения первой версии

- Вопросы поддерживают один вариант, несколько вариантов и соответствие по двум колонкам.
  Варианты редактируются отдельными полями с отметкой правильности. Для соответствий
  определение можно выбрать из списка либо перетащить к термину; определения перемешиваются
  сервером. Вопрос засчитывается только при полностью верном наборе / всех верных парах.
  Свободные ответы и ручная оценка пока отсутствуют.
- Законодательство состоит из отдельных кодексов со вкладками, разделами и статьями.
  Кодекс можно создать пустым, затем наполнить. У статьи номер, название, краткая
  расшифровка и маркер «Важная для ФСО»: такие статьи дублируются сверху своего кодекса.
  Администратор редактирует документы, разделы и статьи непосредственно из справочника.
  В кабинете материалы разделены на законодательство, устав, инструкции и структуру.
- Структура: начальник ФСО и его заместители → УСБ/СБП/АС/КМК → отделы.
  У должностных лиц есть удостоверение формата `123-456` (отдельно от `123_456` при сдаче).
  Звания заместителей начальника ФСО — полковник, начальников управлений — подполковник,
  заместителей начальников управлений и начальников отделов — майор. Только звание
  заместителя начальника отдела допускается оставить пустым. ФИО можно не заполнять.
- Категории банка создаются и переименовываются администратором; старые темы переводятся
  в категории автоматически. В экзамен включаются блоки по нескольким категориям:
  конкретные отмеченные вопросы либо заданное количество случайных вопросов категории.
  В каждом блоке и в попытке нет повторений; общий порядок вопросов перемешивается.
  Тест содержит одну тему. Старые тесты из нескольких тем переводятся в категорию
  с наибольшим числом вопросов; история попыток остаётся прежней.
- Кодовое слово генерируется сервером по кнопке и начинает действовать после сохранения.
  Новые слова хранятся в закрытой БД и видны только администратору. Публичные ответы
  API не содержат ни слова, ни хеша, ни схемы блоков. Старые хеши невозможно прочитать:
  их можно заменить генерацией нового слова. Резервная копия БД содержит эти слова.
- Перед экзаменом посетитель выбирает СБП, АС, Академию или КМК. Администратор задаёт
  доступность экзамена для одного, нескольких или всех отделов; сервер проверяет выбор.
  Экзамены из ранней версии без этой настройки доступны всем четырём отделам.
- Инструкции собираются из заголовков, текста, шагов, списков, предупреждений,
  информационных блоков, изображений и разделителей. Блоки можно переставлять и дублировать.
  Картинки задаются HTTPS-ссылкой или файлом PNG/JPEG/WebP/GIF до 450 КБ; запрос не более 2 МБ.
  В вопрос можно добавить до 6 изображений. Загруженные файлы кодируются в base64 и
  сохраняются в SQLite (локально) / JSONB PostgreSQL (Supabase), а также в снимке попытки.
  Они не зависят от кэша браузера и исходного файла на компьютере. Для полной копии
  изображений нужна резервная копия БД. HTTPS-ссылки зависят от внешнего источника:
  для постоянного хранения самого изображения используйте загрузку файла.
  HTML не исполняется. Старые текстовые материалы остаются доступны.
- Обычный пользователь видит только процент результата теста / экзамена. Сервер
  не отдаёт вопросы, ответы и ключи завершённой попытки через публичные операции.
  Только кабинет администратора показывает ответы сотрудника и допущенные ошибки.
  Пояснения к вопросам убраны из интерфейса.
- После срока сдачи попытка завершается при следующем запросе к системе.
- Тесты тоже сохраняются, но без персональных данных; по умолчанию статистика показывает экзамены.
- Изменения вопросов не меняют начатые/завершённые попытки. Удаление вопроса из банка
  запрещено, пока он включён в состав проверки.
- Пароли и кодовые слова проверяются сервером. Это не система прокторинга:
  сами вопросы тестов и экзаменов доступны участнику во время проверки.
- Нет загрузки PDF и других документов, аудита редактирования, восстановления пароля через интерфейс,
  резервного копирования по расписанию или персональных допусков.
- Используйте данные игровых персонажей. Для резервных копий Supabase настройте
  регулярную выгрузку БД; экспорт CSV результатов не заменяет полную копию.

Внешняя публикация и облачная БД не настроены автоматически: нужны ваш репозиторий
и Supabase-проект. Исходный архив не содержит данных, ранее введённых через
`localStorage` в другом браузере; для них понадобится отдельный экспорт и миграция.
